# 企业管理模块技术方案

## 一、需求概述

用户可以添加并管理多个企业（通过营业执照 OCR 认证），发布招聘时从已认证企业中选择招聘主体，岗位详情页展示企业工商信息并可跳转企业详情页。

**核心功能：**
- 营业执照 OCR 识别，自动回填企业信息
- 企业增删改、设为默认
- 发布招聘时选择企业（无企业跳认证页，1个默认带入，多个弹窗选择）
- 企业详情页（公开）
- 个人中心新增"我的企业"入口

---

## 二、数据库设计

### 新增表：`enterprise`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键，Sonyflake |
| user_id | bigint | 所属用户 |
| name | varchar(100) | 企业名称 |
| social_credit_code | varchar(20) | 统一社会信用代码（唯一标识，不可修改） |
| legal_representative | varchar(50) | 法定代表人 |
| address | varchar(255) | 注册地址 |
| established_date | varchar(20) | 成立日期，如 2019-11-11 |
| business_period | varchar(20) | 经营期限，如 2061-11-11 或 长期 |
| registered_capital | varchar(50) | 注册资本，如 16666.66元 |
| business_scope | text | 经营范围 |
| license_url | varchar(500) | 营业执照图片 OSS URL（不对外公开） |
| is_default | tinyint(1) | 是否默认企业：0=否 1=是 |
| status | tinyint | 1=待审核 2=已认证 3=审核驳回 4=已删除 |
| create_at | datetime | 创建时间 |
| update_at | datetime | 更新时间 |

### 改造表：`job`

新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| enterprise_id | bigint | 关联企业 ID，0 表示未关联 |
| recruit_num | tinyint | 招聘人数，范围 1-99 |

## 三、API 接口

### 3.1 OCR 识别营业执照

```
POST /enterprise/ocr
认证：StrictAuth
```

**Request**
```json
{
  "license_url": "https://oss.xxx.com/license.jpg"
}
```

**Response**（识别结果供前端回填，用户可二次修改）
```json
{
  "name": "餐饮信息网有限公司",
  "social_credit_code": "91610000XXXXXXXX3X",
  "legal_representative": "张小峰",
  "address": "吉林省通化市二道江区挣钱路1号",
  "established_date": "2019-11-11",
  "business_period": "长期",
  "registered_capital": "100万元",
  "business_scope": "餐饮服务..."
}
```

**说明：**
- OCR 调用第三方服务（阿里云/腾讯云营业执照识别）
- 识别失败时返回空字段，前端提示用户手动填写，不阻断流程
- 当前版本仅做社会信用代码正则校验（18位字母数字），不做人工审核

---

### 3.2 创建企业（提交认证）

```
POST /enterprise/create
认证：StrictAuth
```

**Request**
```json
{
  "name": "餐饮信息网有限公司",
  "social_credit_code": "91610000XXXXXXXX3X",
  "legal_representative": "张小峰",
  "address": "吉林省通化市二道江区挣钱路1号",
  "established_date": "2019-11-11",
  "business_period": "长期",
  "registered_capital": "100万元",
  "business_scope": "餐饮服务...",
  "license_url": "https://oss.xxx.com/license.jpg",
  "is_default": 1
}
```

**Response**
```json
{
  "enterprise_id": 123456789
}
```

**业务规则：**
- `social_credit_code` 正则校验（18位），同一用户同一 `social_credit_code` 不可重复添加
- `is_default=1` 时，将该用户其他企业的 `is_default` 全部置 0
- 当前版本创建后 status 直接置为 2（已认证），跳过人工审核环节

---

### 3.3 修改企业信息

```
POST /enterprise/update
认证：StrictAuth
```

**Request**（所有字段可选，传哪个改哪个）
```json
{
  "id": 123456789,
  "name": "餐饮信息网股份有限公司",
  "legal_representative": "张小峰",
  "address": "吉林省通化市二道江区挣钱路88号",
  "established_date": "2019-11-11",
  "business_period": "2061-11-11",
  "registered_capital": "16666.66元",
  "business_scope": "软件技术开发...",
  "license_url": "https://oss.xxx.com/new_license.jpg",
  "is_default": 1
}
```

**业务规则：**
- `social_credit_code` 不允许修改
- 仅限企业所有者操作，否则返回 403

---

### 3.4 删除企业

```
POST /enterprise/delete
认证：StrictAuth
```

**Request**
```json
{
  "id": 123456789
}
```

**业务规则：**
- 软删除（status=4）
- 若被删除的是默认企业，清空 `is_default`，前端引导用户重新设置
- 仅限企业所有者操作，否则返回 403

---

### 3.5 设为默认企业

```
POST /enterprise/set_default
认证：StrictAuth
```

**Request**
```json
{
  "id": 123456789
}
```

**业务规则：**
- 将该用户所有企业 `is_default` 置 0，再将目标企业置 1
- 目标企业必须属于当前用户且 status=2

---

### 3.6 我的企业列表

```
POST /enterprise/my
认证：StrictAuth
```

**Response**
```json
{
  "list": [
    {
      "id": 123456789,
      "name": "餐饮信息网有限公司",
      "social_credit_code": "91610000XXXXXXXX3X",
      "legal_representative": "张小峰",
      "status": 2,
      "is_default": 1
    },
    {
      "id": 123456790,
      "name": "西安餐饮信息网餐饮集团2",
      "social_credit_code": "91610000YYYYYYYY3Y",
      "legal_representative": "李四",
      "status": 2,
      "is_default": 0
    }
  ]

```

**业务规则：**
- 不返回 status=4（已删除）的记录
- 默认企业（is_default=1）排在列表第一位

### 3.9 改造：发布岗位接口

`POST /jobs/create` 新增字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| enterprise_id | int64 | 否 | 关联企业 ID |
| recruit_num | int | 否 | 招聘人数，1-99 |

**进入发布页的企业判断逻辑（前端处理，后端校验）：**
| 场景 | 行为 |
|------|------|
| 无企业 | 跳转企业认证页，认证完成后返回发布页 |
| 1个企业 | 自动带入默认企业，`enterprise_id` 默认填充 |
| 多个企业 | 弹窗选择，带入上次使用的默认企业，`enterprise_id` 必填 |

**后端校验规则：**
- `enterprise_id` 若传值，必须属于当前用户且 status=2
- `recruit_num` 若传值，范围 1-99

### 3.10 改造：岗位列表/详情响应

`POST /jobs/list` 和 `POST /jobs/info` 响应中新增字段：

```json
{
  "enterprise_id": 123456789,
  "enterprise_name": "餐饮信息网股份有限公司",
  "recruit_num": 3
}
```


## 五、开发顺序

1. **数据库** — `enterprise` 表 migration，`job` 表新增 `enterprise_id`/`recruit_num`
2. **model** — `internal/model/enterprise.go`
3. **基础 CRUD** — repository → service → handler → router
   - `/enterprise/create`
   - `/enterprise/my`
   - `/enterprise/delete`
   - `/enterprise/set_default`
   - `/enterprise/update`
4. **公开接口** — `/enterprise/detail`、`/enterprise/select_list`
5. **OCR 接口** — `/enterprise/ocr`，对接第三方 OCR 服务
6. **岗位联动** — 改造 `/jobs/create`、`/jobs/list`、`/jobs/info`
7. **Wire 注册** — 更新 `wire.go`，运行 `wire` 重新生成 `wire_gen.go`
8. **Swagger** — 运行 `make swag`
